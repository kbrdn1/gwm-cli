# [0.10.0-rc.1] - 2026-06-10

Delta against v0.9.0. Merged PRs: #273, #274, #276, #277, #280, #282, #284, #286, #288.

The Settings-editability + TUI enrichment release. The **Settings panel** (`4`) goes
fully editable — category tabs (Theme / Worktree / TUI / All), a per-project ↔ global
layer selector, real toggles / choices / numeric inputs / free-text fields, live
persistence into TOML and on-the-fly apply. On top of that: the **Working Tree** pane
gains colour-coded nerdfont changed-file counts (created / modified / deleted) that
also recolour the file rows, the **Status** pane gains a `Diff +ins -del` line vs the
base branch, and the **Issue/PR** table and pane are enriched with `●/●` pastilles, nerdfont
state-chip badges, cached GitHub state that survives restarts, and a periodic
`[tui].auto_refresh_secs` auto-refresh. The async-task spine gains two new consumers:
create-worktree and quit-wait, so neither blocks the render loop. No CLI or config-schema
change apart from the new `[tui].auto_refresh_secs` key.

### Added

- ✨ Settings panel (`4`, renamed from Configuration) is now editable: category tabs
  (Theme / Worktree / TUI / All) with the edit layer shown as a subtitle, a per-project ↔
  global edit-layer selector (`L`), real toggles / choices (theme preset, sidebar position,
  open mode), numeric input (confirm countdown), and text inputs (worktree base + patterns,
  open shell / editor commands). Edits persist into the chosen layer's TOML and apply live;
  a global edit shadowed by a `.gwm.toml` override is surfaced rather than silently dropped.
  The read-only resolved config lives under the `All` tab
  ([#279](https://github.com/kbrdn1/gwm-cli/issues/279)).
- ✨ Scrollable modal bodies (Keybindings, Settings) now render a herdr-style scrollbar
  ([#279](https://github.com/kbrdn1/gwm-cli/issues/279)).
- ✨ Reusable dedicated-area `LoaderWidget`; the delete-worktree modal is the first real
  consumer, showing both in-flight and failed delete states
  ([#257](https://github.com/kbrdn1/gwm-cli/issues/257)).
- ✨ Sidebar `Working Tree` pane bottom-right footer breaks the changed-file tally into
  colour-coded nerdfont counts — created (green), modified (yellow), deleted (red) — derived
  from `git status --short`, each segment shown only when non-zero (clean tree shows nothing).
  Every file row is recoloured by the same change category; the previous staged-vs-worktree
  cyan column split is retired
  ([#287](https://github.com/kbrdn1/gwm-cli/issues/287)).
- ✨ Sidebar `[2] Status` pane now shows a `Diff +<ins> -<del>` line (insertions green,
  deletions red) for the branch versus its base trunk, using three-dot
  `git diff --shortstat <base>...HEAD` semantics. Hidden when no base resolves, when HEAD is
  the trunk itself, or when the branch has no committed diff yet
  ([#287](https://github.com/kbrdn1/gwm-cli/issues/287)).
- ✨ Worktree table renders Issue/PR as two slots `●/●`, `●/-`, `-/●`, or `-/-` (left =
  Issue, right = PR; `-` means no link; the main worktree keeps its `★`). The Issue/PR pane
  leads each line with a nerdfont dev glyph and badges the link source (` auto ` / ` detected
  `) and GitHub state (` open ` / ` closed ` / ` draft ` / ` merged `) as version-style
  reverse-video chips
  ([#283](https://github.com/kbrdn1/gwm-cli/issues/283)).
- ✨ `[tui].auto_refresh_secs` controls periodic TUI worktree refreshes. Default is `60` s;
  `0` disables. Exposed in the Settings panel under the TUI tab
  ([#285](https://github.com/kbrdn1/gwm-cli/issues/285)).
- ✨ Project tooling ships a Flippad-style coloured `Makefile` plus Zed tasks for the local
  Rust workflow (`build`, `test`, `clippy`, `doctor`, `audit`, worktree bootstrap, and
  related shortcuts).

### Changed

- 💄 Statusbar and modal which-key hints drop the reverse-video badge for a flat "accent bind
  + muted action" treatment; action buttons keep their chip style. Keybindings and Command
  Logs overlays scroll their body only, keeping title and footer hints pinned, with a
  herdr-style scrollbar. Command Logs separates entries with a full-width dashed rule and
  copies the whole transcript to the clipboard with `y`
  ([#279](https://github.com/kbrdn1/gwm-cli/issues/279)).
- 💄 Auto-detected PR (`gh pr list --head <branch>`) is now persisted to a dedicated
  `branch.<name>.gwm-pr-detected` git-config key on `F` refresh. Issue/PR titles and states
  (`gwm-issue-title`, `gwm-issue-state`, `gwm-pr-title`, `gwm-pr-state`,
  `gwm-pr-detected-title`, `gwm-pr-detected-state`) are persisted after successful status
  fetches, so the pane shows cached titles, state chips, and state-coloured icons on startup
  before or during a new fetch. An explicit `gwm link --pr` still wins; a vanished detection
  clears the stored key / title / state
  ([#285](https://github.com/kbrdn1/gwm-cli/issues/285)).
- 💄 Worktree table's first `Created` column and sidebar's `Created` row now use the local
  branch-creation timestamp recorded by `gwm create` (`branch.<name>.gwm-created-at`) when
  available, with trunk-divergence age as a fallback for existing branches
  ([#285](https://github.com/kbrdn1/gwm-cli/issues/285)).
- 💄 Issue/PR pane icons keep two spaces after the glyph with no leading icon padding, and
  use the loaded GitHub state colour (open / closed / draft / merged) instead of always
  rendering muted
  ([#285](https://github.com/kbrdn1/gwm-cli/issues/285)).

### Fixed

- 🐛 Worktrees pane Issue/PR pastilles now switch to loaded GitHub state colours across all
  linked rows after a worktree refresh, so closed issues/PRs no longer fall back to the
  linked-only colours after relist
  ([#285](https://github.com/kbrdn1/gwm-cli/issues/285)).
- 🐛 TUI now kicks off an initial Issue/PR status refresh for all linked worktrees at
  startup when a GitHub remote is available, and worktree refreshes persist refreshed
  Issue/PR state per branch so markers survive closing and reopening the app
  ([#285](https://github.com/kbrdn1/gwm-cli/issues/285)).
- 🐛 Settings free-text fields (worktree base / patterns, open shell / editor commands)
  persist as TOML strings, so a value like `123` or `true` is no longer coerced to a
  number / bool. Config writes validate before touching disk (a rejected edit can never
  overwrite a good config file) while an edit to an already-invalid file is still written
  so `gwm config set` can recover a broken config
  ([#281](https://github.com/kbrdn1/gwm-cli/issues/281)).
- 🐛 Scrollable modal bodies (Keybindings, Command Logs, Settings) compute the
  horizontal-pan bound after reserving the scrollbar column, so the final cell of a long
  line stays reachable
  ([#279](https://github.com/kbrdn1/gwm-cli/issues/279)).
- 🐛 Delete-worktree confirmation no longer blocks the TUI render loop while the removal
  runs; the async spine drives the deletion and quit waits for it like other mutating tasks
  ([#257](https://github.com/kbrdn1/gwm-cli/issues/257)).
- 🐛 Create-worktree submission no longer blocks the TUI render loop while `worktree::add`
  and bootstrap run; the Create modal shows a dedicated loader / failure row and the global
  statusline spinner stays active until completion
  ([#276](https://github.com/kbrdn1/gwm-cli/issues/276)).
- 🐛 TUI quit now waits for in-flight mutating spine tasks (`sync` / `bootstrap` /
  delete-worktree) to finish instead of abandoning them mid-operation
  ([#267](https://github.com/kbrdn1/gwm-cli/issues/267)).

### Tests

  `ubuntu-latest` / `macos-latest` / `windows-latest` matrix. The Settings editability,
  LoaderWidget, Issue/PR pastilles and cached-state logic, Working Tree colored counts,
  Status diff line, and the async create / quit changes are all pinned by state-machine and
  helper tests (`tests/tui_app_tests.rs`, `tests/tui_ui_helpers_tests.rs`,
  `tests/tui_footer_tests.rs`, `tests/tui_theme_audit_tests.rs`) — no ratatui backend
  needed.
