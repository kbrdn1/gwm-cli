# [0.10.0-rc.4] - 2026-06-17

Delta against v0.10.0-rc.3. Merged PRs: #314, #316.

The fourth 0.10.0 train adds the **fleet-chore pair** — two utility
subcommands that act across the whole worktree set instead of one at a time —
and brings the in-repo documentation (EN + `docs/fr/`) fully in line with the
v0.10.0 surface. No breaking changes; the default text output of every command
is unchanged.

### Added

- **`gwm exec [<slug>...] -- <cmd>`** (issue #313) — run a command in each
  worktree, sequentially. Targets every non-main worktree by default, or the
  slugs listed before `--`; everything after `--` is forwarded verbatim (flags
  and all). Prints a per-worktree `✓ / ✗` rollup and exits non-zero if any
  worktree's command failed. A program containing a path separator (e.g.
  `./script`) is anchored to each worktree so it runs that worktree's own copy
  regardless of platform; bare names stay `PATH` lookups. No bootstrap trust
  gate — it's the user's own command against their own worktrees, distinct from
  the untrusted-`.gwm.toml` threat model (#95).
- **`gwm clean [<slug>...] [--yes]`** (issue #313) — report (and with `--yes`
  reclaim) heavy build artifacts (`target/`, `node_modules/`, `dist/`,
  `build/`) across worktrees. Report-only by default. The safety gate deletes
  **only** directories git treats as ignored *and* that hold no tracked files,
  so a tracked or hand-authored `dist/` / `build/` is reported as skipped
  rather than destroyed; symlinks (entries and artifact roots) are never
  followed, so size accounting and deletion stay bounded to the worktree. The
  dry-run preview is classified through the same gate, so its total and its
  "re-run with `--yes`" promise match exactly what a deletion would remove.
  Deliberately not journaled into `gwm history` — the artifacts are
  regenerable.

### Docs

- Full documentation sync to the v0.10.0 codebase (issue #315), EN + the
  `docs/fr/` mirror in lock-step: the CLI reference now documents `gwm review`
  (#308), `gwm exec` and `gwm clean` (#313); the TUI docs cover the Working
  Tree file-tree sidebar, the PR CI indicator, the v0.10 keymap redesign and
  the Settings Keys tab; configuration, integrations, getting-started and
  development pages were verified against `src/` + `examples/`. `ROADMAP.md`
  records the rc.3 and post-rc.3 trains in Shipped highlights. The pass was
  strictly evidence-based — no command, flag, or feature is documented that is
  not in the codebase — and a completeness/parity critic confirmed every
  subcommand is covered with EN/FR parity.
