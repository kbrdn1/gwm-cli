# Roadmap

La roadmap complète (avec les catégories groupées et les liens d'issues par item) vit dans [`ROADMAP.md`](https://github.com/kbrdn1/gwm-cli/blob/main/ROADMAP.md) à la racine du repo. Le tracker d'issues est la source de vérité pour les détails de scope, les critères d'acceptation et les alternatives considérées.

## état courant — stable v0.9.0 / v0.10.0-rc.2 en cours

La ligne **stable** courante est **v0.9.0**. Deux trains de **pre-release** ont depuis atterri sur `dev` et sont en file pour la prochaine release — `v0.10.0-rc.1` (éditabilité des Settings + enrichissement TUI) et un second train post-rc.1 visant `v0.10.0-rc.2`. Les deux sont des pre-releases ; aucune coupe stable pour l'instant. La ligne 0.9.0 s'appuie sur le cycle de configurabilité v0.8.0, puis ajoute le train TUI 0.9.0 :

- **Couverture complète des rôles de thème** ([#170](https://github.com/kbrdn1/gwm-cli/issues/170) / [#210](https://github.com/kbrdn1/gwm-cli/issues/210) / [#211](https://github.com/kbrdn1/gwm-cli/issues/211) / [#214](https://github.com/kbrdn1/gwm-cli/issues/214)) — le `[theme]` résolu est propagé à tous les sites de rendu TUI, avec des rôles dédiés `name`, `path`, `staged`, `modified` et `untracked`. Les valeurs par défaut sont conservées et verrouillées par `tests/tui_theme_audit_tests.rs`.
- **Migration source vers `git2` 0.21** ([#169](https://github.com/kbrdn1/gwm-cli/issues/169)) — le changement cassant d'API d'accesseurs, différé pendant v0.8.0, est maintenant absorbé dans le code source et l'ancien arbre transitif `url` disparaît.
- **Polish de la statusbar, du layout et des modales TUI** ([#217](https://github.com/kbrdn1/gwm-cli/issues/217) / [#220](https://github.com/kbrdn1/gwm-cli/issues/220) / [#222](https://github.com/kbrdn1/gwm-cli/issues/222) / [#224](https://github.com/kbrdn1/gwm-cli/issues/224)) — statusbar contextuelle, spinner animé pendant le fetch GitHub, touches directes de focus (`1` / `2`), sidebar empilée par défaut, overlays plus larges et modales create/link/delete/Issue-PR affinées.
- **Spine de tâches async** ([#231](https://github.com/kbrdn1/gwm-cli/issues/231) / [#255](https://github.com/kbrdn1/gwm-cli/issues/255) / [#258](https://github.com/kbrdn1/gwm-cli/issues/258) / [#256](https://github.com/kbrdn1/gwm-cli/issues/256)) — refresh des worktrees, fetch GitHub, `sync` (`S`) et bootstrap (`b`) tournent maintenant hors thread avec coalescing, abandon des résultats tardifs et progression dans la statusbar au lieu de figer la boucle d'événements.
- **Famille de panes `1` / `2` / `3` / `4`** ([#226](https://github.com/kbrdn1/gwm-cli/issues/226) / [#232](https://github.com/kbrdn1/gwm-cli/issues/232)) — focus direct Worktrees / Status, overlay Command Logs et panneau Configuration affichant la config résolue avec attribution repo / user / default.
- **Touche docs (`.`)** ([#233](https://github.com/kbrdn1/gwm-cli/issues/233)) — ouverture de la documentation depuis la TUI ; rebindable via `open_docs`.

Les notes de release complètes de la v0.9.0 vivent dans [`changelogs/0.9.0.md`](https://github.com/kbrdn1/gwm-cli/blob/main/changelogs/0.9.0.md). La MSRV est **1.86** (relevée dans le train rc.2 par les dépendances `portable-pty` / `tui-term` de l'overlay PTY).

## v0.10.0-rc.1 — en cours sur dev

`v0.10.0-rc.1` (2026-06-10) est la première pre-release du cycle **éditabilité des Settings + enrichissement TUI**. Notes RC complètes : [`changelogs/pre-releases/0.10.0-rc.1.md`](https://github.com/kbrdn1/gwm-cli/blob/main/changelogs/pre-releases/0.10.0-rc.1.md). Points clés :

- **Panneau Settings éditable** ([#279](https://github.com/kbrdn1/gwm-cli/issues/279)) — onglets de catégories (Theme / Worktree / TUI / All), sélecteur de couche projet ↔ global (`L`), persistance en temps réel dans le TOML avec application à la volée ; scrollbar herdr-style sur toutes les modales défilables.
- **Compteurs colorés Working Tree** ([#287](https://github.com/kbrdn1/gwm-cli/issues/287)) — compteurs nerdfont créés / modifiés / supprimés dans le footer + recoloriage des lignes correspondantes ; ligne `Diff +ins -del` vs base dans le pane Status (sémantique three-dot).
- **Enrichissement Issue/PR** ([#283](https://github.com/kbrdn1/gwm-cli/issues/283) / [#285](https://github.com/kbrdn1/gwm-cli/issues/285)) — pastilles `●/●` dans la table des worktrees, badges nerdfont avec chips d'état GitHub, état GitHub mis en cache (titres + états survivent aux redémarrages), refresh initial au démarrage, auto-refresh périodique via `[tui].auto_refresh_secs`.
- **Loaders async** ([#257](https://github.com/kbrdn1/gwm-cli/issues/257) / [#276](https://github.com/kbrdn1/gwm-cli/issues/276) / [#267](https://github.com/kbrdn1/gwm-cli/issues/267)) — `LoaderWidget` réutilisable, create-worktree et quit-wait asynchrones sur la spine (delete, create et quit ne bloquent plus la boucle de rendu).

## v0.10.0-rc.2 — en cours sur dev

Un second train post-rc.1 a atterri sur `dev`, en file pour `v0.10.0-rc.2`. Delta complet : [`CHANGELOG.md`](https://github.com/kbrdn1/gwm-cli/blob/main/CHANGELOG.md) `[Unreleased]`. Points clés :

- **Overlays PTY embarqués** ([#35](https://github.com/kbrdn1/gwm-cli/issues/35)) — `l` / `L` ouvrent lazygit et `o` / `O` ouvrent une session `$SHELL` native à l'intérieur de la TUI (sans bascule d'écran alterné ; `Esc` ferme), propulsés par `portable-pty` + `tui-term`. Cela relève la MSRV à **1.86**.
- **Refonte du keymap TUI** ([#290](https://github.com/kbrdn1/gwm-cli/issues/290)) — bindings unifiés de la liste (`p` / `P` pull / push, `c` edit-worktree, `e` exit-to-worktree, `y` / `w` yank, `t` pane multiplexeur, `h` / `H` macros) plus les commandes utilisateur `[tui.macro1]` / `[tui.macro2]`. Les slugs pré-#290 chargent encore via des alias de rétrocompatibilité.
- **Touches de modales contextuelles rebindables** ([#219](https://github.com/kbrdn1/gwm-cli/issues/219) / [#294](https://github.com/kbrdn1/gwm-cli/issues/294)) — chaque verbe de modale est remappable sous des tables imbriquées `[tui.keys.modal.<context>]`, et le panneau Settings gagne un onglet **Keys** pour éditer chaque binding en direct (capture de touche + write-back validé).
- **Mode workspace multi-repos** ([#36](https://github.com/kbrdn1/gwm-cli/issues/36)) — `gwm --workspace ~/Projects` (et l'auto-détection de `gwm` seul) ouvre la TUI sur chaque dépôt git situé un niveau sous une racine, avec une colonne REPO ; `gwm list --workspace` affiche la table fusionnée ; `gwm create --repo <name>` choisit la cible.
- **Presets de configuration** ([#37](https://github.com/kbrdn1/gwm-cli/issues/37)) — `gwm init --preset <name>` amorce un `.gwm.toml` opinionné pour `laravel` / `node` / `nuxt` / `rust` / `go` / `python-uv` / `generic` ; `--list-presets` les énumère, `--show` imprime le TOML résolu sans écrire.
- **API JSON + daemon** ([#38](https://github.com/kbrdn1/gwm-cli/issues/38)) — `--format=json` sur `gwm list` / `doctor` / `path` (schémas stables sous `docs/schema/`), et `gwm daemon`, un serveur JSON-RPC 2.0 sur une socket unix avec les méthodes `list` / `doctor` / `path` plus un flux de notifications `subscribe`, pour l'intégration éditeur / statusbar.
- **Sidebar Status** ([#299](https://github.com/kbrdn1/gwm-cli/issues/299) / [#300](https://github.com/kbrdn1/gwm-cli/issues/300)) — la section Issue/PR fait remonter l'état CI global de la PR liée (passing / failing / running, dérivé du rollup déjà récupéré), et le pane Working Tree rend `git status` en arbre de fichiers nerd font coloré par git.

## la suite

Les deux trains de pre-release v0.10.0 (rc.1 et le train rc.2 ci-dessus) sont maintenant sur `dev`, en file pour `v0.10.0-rc.2`. Les items plus larges précédemment listés — overlay PTY (#35), mode workspace multi-repos (#36), presets de configuration (#37) et API JSON-RPC + daemon (#38) — ont tous été livrés dans ce train.

Nouvelle direction — boucler le cycle GitHub (revue de manques post-rc.2) :

- [#308](https://github.com/kbrdn1/gwm-cli/issues/308) — `gwm review <PR#>` : matérialiser une PR / branche distante **existante** dans un worktree. Aujourd'hui chaque feature worktree⇄GitHub est sortante uniquement ; ceci ajoute la moitié entrante pour checkout la PR d'un collègue en isolation et la review / tester / corriger, transformant l'indicateur CI de rc.2 (#299) en workflow de review complet.
- [#309](https://github.com/kbrdn1/gwm-cli/issues/309) — un premier consommateur pour `gwm daemon` (#38) : un statusline one-liner léger sur le flux `subscribe` plus une recette éditeur, pour que le protocole soit exercé par un vrai client.

Entretien :

- [#304](https://github.com/kbrdn1/gwm-cli/issues/304) — suivi workspace (items de review nuancés restés ouverts après l'atterrissage de la PR multi-repos #303).
- [#206](https://github.com/kbrdn1/gwm-cli/issues/206) — captures d'écran de la doc (remplacer les placeholders provisoires par de vraies captures de la TUI).

## comment contribuer

1. Choisissez une issue ou ouvrez-en une nouvelle avec `--label enhancement` / `--label bug` décrivant le scope.
2. `gwm create <type> <issue> <slug>` pour démarrer un worktree isolé (l'issue s'auto-link — voir [linking GitHub](/fr/integrations/github-linking#détection-automatique)).
3. Suivez les conventions de [`CONTRIBUTING.md`](https://github.com/kbrdn1/gwm-cli/blob/main/CONTRIBUTING.md) — voir [Contribuer](/fr/development/contributing) pour la version site-de-docs.
4. Ouvrez une PR ciblant `dev`. Les releases stables sont publiées via une PR de merge `dev → main` suivant la convention `🔀 chore(release): merge dev → main for vX.Y.Z`.
